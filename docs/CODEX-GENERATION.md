# 使用 Codex 生成可导入的 UI

打开顶部 **Codex 生成任务**，选择角色详情、背包、商店、游戏 HUD、空白画布或当前设计副本，填写名称、画布尺寸、页面需求和美术限制。导出不会替换或修改当前项目。

点击 **导出任务包 → 下载任务 ZIP**，把 ZIP 交给 Codex：

> 读取 TASK.md 和 task.json，按需求生成可编辑 UI。使用模板的原生组件与素材，运行 `node validate.mjs result.project.json` 后返回 result.project.json，并列出未满足的要求。不要将整张页面变成图片，不要返回 HTML 代替项目文件。

拿到结果后，使用顶部 **导入 UI** 打开 `result.project.json`。检查组件数与尺寸，保留导入前备份，再确认替换。模板中的按钮、文字、面板和美术均为独立可编辑组件。已有页面的局部修改继续使用“评论 → 反馈包 → 增量补丁”流程。

任务包包含：

- `TASK.md`：操作说明与真实能力边界。
- `task.json`：本次需求、限制、源项目版本和目标尺寸。
- `template.project.json`：可直接导入的原生起始模板；Codex 基于它产生结果。
- `FORMAT.json`：支持的节点类型、项目字段和布局规则。
- `asset-manifest.json` 与 `assets/`：素材元数据及保持原始字节的参考副本。
- `model.mjs` 与 `validate.mjs`：工具的真实校验器，不需要安装 npm 依赖。
- 可选 `reference.project.json`：当前完整设计。关闭“包含当前设计作为参考”能减少 Codex 读取量。

任务包沿用当前项目的设计规范和素材库。它不调用付费 API，也不与云端 Codex 自动建立连接。云端用户手动交换 ZIP 和 JSON；本地 Codex 可以直接读取解压目录。

模板用于验证结构和协作流程，最终美术需要独立验收。“当前设计副本”按选定画布尺寸缩放组件，保留原组件 ID 和锁定标记，清空旧评论与修改历史；其他模板具有新的可编辑布局。它们都创建新项目候选，不会暗中改变运行中的设计。

包中的素材副本路径不是项目素材路径。结果应保留原 `/assets/...` 或 `/local-assets/...` 引用，并在导出任务包的同一安装中导入。跨机器使用时，应先通过目标工具素材库导入素材，再更新到返回的素材 ID 和路径。当前包没有一键跨机器恢复素材的功能。

校验器检查 JSON 结构、组件关系和素材引用 ID；它不能确认目标安装中的文件是否存在，也不运行 Godot 或评判画面质量。Godot 与美术验收必须分别完成。
