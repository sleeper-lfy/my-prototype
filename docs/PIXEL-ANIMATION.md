# 像素角色动画（v0.4.0）

从顶部选择“像素动画 / Pixel animation”。默认画布为 **64×96 像素**，内置简化人形骨架及上、下、左、右四个方向的待机、行走、攻击示例。示例角色由确定性的像素绘制程序生成，供动作与审阅流程验证；最终角色美术应独立验收。

## 编辑和播放

选择动作与方向，在时间轴选择帧。可播放、暂停、逐帧查看，调整播放速度和整数倍缩放，开启骨架、网格、地面线和洋葱皮。预览采用最近邻像素显示，不以平滑放大掩盖像素边缘。

骨骼角度、根节点位置和帧时长由结构化数据保存。骨骼决定运动，部件贴图决定外观。重新计算动作不会创造角色背面、遮挡部分或方向性装备；方向美术需要用户提供。低分辨率部件旋转仍可能需要手工修帧。

## 导入与素材

可以导入工具原生动画 JSON，也可以将规则精灵图按画布宽高切分为当前动作的帧。导入后的完整帧图片用于逐帧审阅，不自动反推成可编辑的骨骼。身体部件可绑定到骨骼，锚点决定部件围绕哪个像素旋转。

原生动画 JSON 包含像素数据、动作、稳定帧 ID 和评论，适合本地文件交换。当前动画是独立文档，不包含在 v0.3 项目工具箱的 UI/地图 ZIP 中；请用动画工作区的“导出项目”备份。动画工作文档独立于 UI 和地图文档；切换工作区不会把动画写入 UI 项目。

## 组件级评审与 Codex

评论可以定位动作、帧范围和身体部位，记录目标、期望效果、禁止修改属性、优先级及状态。评论通过稳定帧 ID 关联；调整时长和姿势不会改变帧 ID。

导出反馈包后，将 ZIP 交给 Codex。包中包含本轮待处理评论、必要动作与骨架信息、实际帧 PNG 及约束。Codex 应返回局部 JSON 补丁。导入补丁后先查看字段和画面差异，再应用；过期版本和受保护字段会被拒绝。

历史记录提供回退。回退同样检查当前版本，不应以恢复旧文件的方式覆盖后续工作。用户负责验收评论，Codex 不应自行标记为已通过。

完整协议见 [Codex 动画参考](../.agents/skills/game-ui-studio/references/pixel-animation.md)。已有 UI 的 `review.mjs` 不直接处理动画文档。

## 检查与 Godot

检查包括数据有效性、画布裁切、空白帧、半透明像素、调色板越界、极端关节旋转、脚底接触移动、循环首尾突变和相邻帧轮廓变化。脚底、循环和轮廓诊断只能提示问题，不代表美术质量合格；请结合连续播放与逐帧对比复核。

Godot 导出采用 `AnimatedSprite2D` 和 `SpriteFrames`，包含实际 PNG、帧时长及 `animation-map.json` 稳定 ID 映射。打开导出的 `project.godot` 后可以实际播放动作，用方向键切换。配套脚本通过 `animation_event` 信号发出帧事件，游戏需要自行连接业务逻辑。骨架与 IK 留在 Studio 文档中；碰撞与接触元数据不自动成为游戏物理行为。导出 ZIP 成功、Godot 导入成功、运行截图与美术验收是不同结果，请以各自验证报告为准。

此工作区优先实现本地离线评审与参数生成，不依赖付费模型 API。云端 Codex 无法直接访问用户电脑的 localhost，使用文件交换；本地 Codex 才能调用正在运行的本地服务。
